# 电商图排版设计

在原Campaign、制作卡和图型规则上细化版式。以下比例为设计起点，不是平台规则或模型像素精确保证；用户版式、实际画幅和真实商品结构优先。

## 先定信息预算，再选布局

每张先确定一个主要购买主题、主视觉和信息层级；同一主题下可组合多项相关卖点与证据。用户要求充实时按 [内容充实与辅助视图](content-depth-and-supporting-visuals.md) 配置足够大的缩略图、局部、图标或状态对照；不把一处证据当作信息上限。尺寸/清单按组组织。信息超出容量时按顺序处理：删除重复→缩短文案→合并标签→拆模块；最后才适度调整字号，不把必要条件缩成不可读文字。

商品层、主标题层、证据/副文层、声明层明确分工。阅读顺序由本图职责决定：外观图先商品，利益图可先短标题，规格图先对象与尺寸关系。不要让徽章、亮色道具和过大数字抢走主信息。

## 布局库

| ID | 适合任务 | 设计起点 | 易错点 |
|---|---|---|---|
| L1 完整主体 | 主图/外观识别 | 完整商品居中或轻偏，关键部件清晰；主图无新增字 | 为放大占比裁屋顶、脚座、包装 |
| L2 图文双区 | 单利益/宽幅A+ | 图像约55–70%，信息约30–45%；两区可有留白缓冲 | 文字区叠上关键结构，区域总宽超画布 |
| L3 主体+近景 | 结构/工艺证据 | 主体为主，1–2个足够大的细节窗或真实局部 | 圈出并不存在的部位，细节太小，错引线 |
| L4 横向/纵向步骤 | 安装/操作 | 2–4个已确认步骤起步，同级图等大小 | 虚构隐藏动作，步骤方向混乱，承诺时长 |
| L5 尺寸/选择 | 尺寸/兼容 | 实物或准确示意+尺寸标注/紧凑参数组 | 数字与端点不对应、比例暗示错误、单位漏失 |
| L6 多情境 | 真实多场景/对照 | 2–3个有不同任务的面板，各自保留完整对象 | 每格过小、虚构前后效果、商品漂移 |
| L7 场景+信息轨 | 生活方式/横幅 | 大幅场景+平静文字区/底栏，信息避开主体轮廓 | 用底栏遮脚座，背景杂乱导致字不可读 |
| L8 证据卡/比较表 | 真实数据/系列选择 | 对齐维度、对象、单位与条件，用足够留白区分组 | 用星级或勾叉暗示无依据优越性，塞满小字 |

布局ID用于策划记录，不是要求用户记编码。具体Prompt必须写出区域与内容，不能只写“使用L2”。

## 空间与文字规格

- 建立归一化区域，左上(0,0)、右下(100,100)。分别给主体、文字、细节、声明的范围；范围可相邻，关键内容不互相遮挡。产品占比说明是画布宽度、高度还是面积，避免混用。
- 外边距可从画布宽/高的4–6%起步，栏间距2–4%；按真实平台裁切区调整。近景任务可裁非关键范围，完整主图/整体识别任务不能裁商品。
- 标题可从正文字号约1.8–2.5倍起步，最多1–2行优先；正文和声明采用可读的次级层级，不能因层级低就无限缩小。字重、对齐和间距胜过大量描边与特效。
- 在预期展示宽度检查字的实际大小：例如1464宽图片缩到366宽时，48px原图文字约为12px显示。这是缩放计算，不是平台字号规定；过小应重排或提供移动版本。
- 先按最终文字长度估计可用行宽，英文断行保留词组，中文避免孤字，品牌/型号/数字单位不随意拆开。图像模型不能保证指定字体精确复现，描述字形风格与层级，生成后看实际效果。
- 背景优先选择平静区域，必要时加克制底板或渐变承托文字；不靠粗描边修补所有对比问题。颜色与品牌保持一致，数据色和装饰色不混淆。

## 图形与证据对应

引线从对应标签指向真实部件，端点不落空；放大窗需要匹配原部位、方向与外观。图标只作导航或准确结构表达，不虚构防水/防火/认证徽章。尺寸箭头按真实测量对象给端点，不画成漂浮装饰。

## 桌面与手机、长图衔接

桌面转手机时按 [手机端重排流程](mobile-adaptation.md) 独立设计场景、机位和信息区，保留同一SKU、主题、关键条件和Campaign。600×450是常用4:3画幅与排版基准，非一律固定的交付像素上限；允许900×675、1200×900等同比例高清成品，实际后台或用户明确的精确像素要求优先。提高导出像素不增加手机端的信息预算；按实际显示宽度验字。实际平台仅支持一种素材时，在该素材可读性内控制信息量，不声称系统会自动使用另一版本。

长图按屏独立检查，再看全长：模块间沿用网格、色带、标题节奏与分隔，不能在拼接处截断商品/文字或把一条主张和条件拆到相距很远的屏。横幅与方卡不强制同主体占比，避免拉伸适配。

## 排版验收

逐张原尺寸检查文字与引线，再按实际缩略宽度检查阅读路径；整套接触表只用于一致性，不能代替细字验收。未生成时记录“排版目标已检查、实际成图待验”，不能声称已经验证清晰。预览图与最终文件分开，重排不覆盖正确旧版。
