# Amazon Listing 图片生产 SOP

本 SOP 将 Listing 图片生产标准化为可审计的八个关卡。它不代替目标站点后台的当期图片政策；上架人必须在发布前确认实际类目、站点和后台要求。

## 关卡与交付物

| 关卡 | 进入条件 | 必交付物 | 退出条件 |
|---|---|---|---|
| -1. 竞品视觉研究 | 用户未明确跳过，且提供公开类目页、关键词和站点 | `00_research/competitor-visual-intelligence.md` 或阻断记录 | 已下载图库均有来源；逐图标注与市场机会完成；或已记录跳过 / 阻断原因 |
| 0. Brief | 已知产品或有待补资料 | `00_brief/amazon-listing-brief.md` | 产品参考、站点、图片数量、事实状态和目标明确；缺失项已列出 |
| 1. 事实冻结 | Brief 已填写 | A/B/C 事实分级 | A 级可视觉化；B 级待确认；C 级禁止进入提示词和文案 |
| 2. 图序计划 | 事实冻结 | `01_plan/image-plan.md` | 每图只有一个购买问题、一个规格和 P0 验收点 |
| 3. 提示词 | 图序已批准 | `02_prompts/` 中每图一份英文提示词和预检报告 | 所有 lint error 已修复；逐字文案与版式已进入实际成品提示词 |
| 4. 成品生成 | 完整提示词通过 | `03_generated/` | 主图先通过；附图直接含文案和排版，每图无 P0/P1 |
| 5. 成品 QC | 已生成完整候选 | `04_layout/` 版式核对、`05_qc/` | 文案逐字、数据、引线和移动端阅读通过；参考对照和质量闸门完成 |
| 6. Final | QC 通过 | `06_final/` 和 `delivery-report.md` | P0/P1 均关闭；平台最终复核责任已标记 |

## 竞品视觉研究关卡

竞品研究默认优先于图序规划，但不是无条件爬取任务。只有在用户提供公开 Amazon 类目 / Best Sellers 页、目标站点和关键词时才执行正常公开访问；遇到验证码、限流、访问控制、输入缺失或用户明确跳过时，停止研究并记录状态。不得将“未研究”描述为“市场洞察”。

研究的最小交付物是 `00_research/competitor-visual-intelligence.md`。它必须区分三层内容：

1. **可验证观察**：从已下载商品图库中观察到的图序、机位、背景、商品占比、文字密度、场景角色和可见结构证据。
2. **抽象市场方法**：例如“多数竞品先用白底完整展示，再用细节图回答结构问题”。不得提取或改写竞品文案、认证、性能结论或商品事实。
3. **自有图需机会**：只能映射到本 SKU 已确认的 A/B/C 事实分级；A 级可规划成品，B 级等待资料，C 级禁止成为自有卖点。

竞品图片绝不可作为自有 Listing 图片素材、训练素材、Logo / 文案来源、产品结构来源或独特场景布局蓝本。报告的价值在于决定“回答什么问题、用什么类型的证据”，而非决定“复制哪一张图”。

## 默认七图结构

除非用户要求的图数或资料不足，否则按下列顺序规划。每张图都可因没有可证实的资料而被删除或替换，不能用猜测的卖点补位。

| 图号 | 类型 | 唯一购买问题 | 数据 / 文案边界 |
|---|---|---|---|
| 01 | 主图 | 这是什么，完整售卖商品是什么样 | 无文字、无道具、无非售卖物；按目标站点规则复核 |
| 02 | 核心卖点 | 为什么值得购买 | 仅一个已证实卖点；直接生成含文案与版式的成品 |
| 03 | 结构功能 | 它如何工作或如何与众不同 | 用可见结构或已确认使用状态证明 |
| 04 | 材质细节 | 做工和关键材料外观如何 | 只描述参考图可见或已确认的材料事实 |
| 05 | 尺寸 / 适配 | 是否适合我的空间或用途 | 只用已确认尺寸、单位和兼容性；直接生成并逐项核对 |
| 06 | 场景 | 在真实使用环境中是什么效果 | 道具不遮挡商品且不暗示为包含物 |
| 07 | 包装 / 使用 / 服务 | 我会收到什么或下一步如何使用 | 仅使用已确认清单、步骤或服务政策 |

## 主图关卡

主图必须先完成并单独验收，才生产附图。其内部通过标准：

- 完整商品清晰可见、自然比例、关键部件不裁切或遮挡；
- 背景、文字、道具、人物、包装、徽章、图标、边框、Logo、水印及非售卖物符合目标站点当期政策；
- 产品结构、颜色、材料外观和已含配件与事实冻结一致；
- 无未证实尺寸、认证、性能、价格、折扣、评价或绝对化宣称。

## 文件命名

使用稳定且便于追溯的文件名，不含未验证的卖点：

```text
01_main-generated-v01.png
02-core-benefit-generated-v01.png
03-structure-generated-v01.png
05-dimensions-generated-v01.png
01_main-final-v01.png
```

同一图修订使用递增版本号；不要覆盖已通过的成品。返工记录必须说明“保留什么、只修什么、复检结果”。

## 交付判定

“可交付”只表示本 SOP 中的图像与事实 QC 已通过，不表示 Amazon 自动批准。以下任一情况不可进入 `06_final/`：

- P0/P1 缺陷未关闭；
- 文案、尺寸、性能、包装或认证无资料来源；
- 主图含疑似不符合目标站点政策的元素；
- 生成过程被报告为原 SKU 保真，但实际替换了未被批准的结构或配件；
- 尚未按上架方适用要求处理 AIGC 标识、元数据或权利确认。
