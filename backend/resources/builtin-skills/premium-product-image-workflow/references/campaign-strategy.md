# 策略与图内文案

吸收 ecommerce-visual-copywriting 的证据账本、购买理由与逐图策略，以及 ecommerce-image-suite 的商品信息组织。上游问卷与留白默认值不导入。先用 [卖点提炼](selling-point-extraction.md) 建候选池，再按 [卖点到分镜](selling-point-storyboard.md) 规划图序；输出使用 [工作簿](../assets/selling-point-workbook.md)。

## 模式与购买驱动力

只提炼卖点时交购买理由、证据、排序与缺口，不自动生图；完整策划继续制作卡和提示词；审查/改稿只修有问题的内容；设计师交接交最终文字、排版、参考角色与验收点。不强制一次问卷或逐张确认。

选一个主驱动力，必要时一个辅驱动力，不默认所有产品都卖痛点：

| 驱动力 | 买家问题 | 视觉与证据重点 |
|---|---|---|
| 视觉/质感 | 是否符合我的审美与空间/穿搭？ | 真实配色、比例、纹理、造型；不由光泽推断材料等级 |
| 痛点/效率 | 能解决哪个具体麻烦？ | 核实结构/操作/步骤；节时或效果比较需测试 |
| 理性/参数 | 是否符合我的使用条件？ | 规格、接口、容量、兼容与适用边界 |
| 信任/证据 | 为什么相信这项主张？ | 对应SKU资料、实物细节与检测范围 |
| 情绪/身份 | 我想如何使用、搭配或送礼？ | 有实际使用基础的场景与审美，不冒充性能保证 |
| 价格/组合 | 实际买到什么、什么条件下划算？ | 件数、币种、优惠条件与有效期；不造原价和稀缺 |

从已有资料确定平台/市场、图型、身份、用户和购买疑问。资料充分就执行；缺品牌系列名不必停工，可用已有SKU或通用品类作内部标签，不擅造消费者可见品牌名。

每张图串起：**可验证特征 → 对用户的意义 → 可见证据 → 文案**。没有证据的性能不能通过“可能、更好、有助于”转成卖点。氛围标题可描述活动与感受，不暗示容量、包含物或防护等级。

证据账本包含 claim_id、文字、来源文件/页码/图号、SKU、事实等级、确认状态与限制。数字、单位、认证、服务承诺绑定来源。用户口述记为口述；需正式证明的内容不能仅靠口述升级。可见外观可作身份与外观描述，不能升级为工艺、材料成分或性能凭证。冲突、待补证与已排除分开记录；条件性结论保留条件，竞品资料不支持本品性能。

## 文案

按 [照片推测卖点](photo-inferred-selling-points.md) 主动提出材质/性能候选、置信度、依据与展示方案；上述限制针对把推测当作已确认成品宣称，不禁止探索和概念策划。

- 标题回答本图主要问题；副文和相关支撑模块提供新增信息。普通简洁图可用一个标题、一行副文和必要标签；用户要求丰富内容时按主题组织多个子卖点及其证据，不以“一行副文”限制内容，也不机械凑三条。
- 按市场本地化表达、场景与单位；数值换算保留原始数据和依据。
- 精确列出消费者可见文字、标点、大小写与断行，不自动全大写或拆品牌拼写。
- “待确认”“同上”等工作说明只在稿外；未知项省略，不印在成品上。
- 道具不包含的声明清晰可读；有条件的主张把条件放在对应信息附近。
- 主图无新增文字；包装原文保真不能成为加广告字的借口。

继续使用原 `listing-image-requirements.md` 与 `assets/listing-image-requirement-card.md`，补充购买理由、claim_id、首个视觉落点和阅读顺序。无研究时写“无竞品洞察”。

自审按 [文案质量与审查](copy-review.md) 采用通过/待修复/不适用及证据，覆盖事实、转化、视觉层级、一致性与可执行性，不强制凭空打80分。策划通过不代表成图通过。宣称按 [平台与品类适配](market-category-adaptation.md)、实际市场和当前规则评估，不复制上游政策结论。
