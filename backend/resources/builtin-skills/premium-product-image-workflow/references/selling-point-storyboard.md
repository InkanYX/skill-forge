# 从卖点到图片策划

综合来源技能的 Storyboard 角色、8类套图、动态提示词、布局与模特一致性方法。图型是选择工具，不是每套必须生成的清单。39类场景目录只负责定位画面，不替代卖点判断。

## 按购买决策分配职责

| 角色/图型 | 决策问题 | 常用证据与画面 |
|---|---|---|
| Hero/KV1/白底 | 这是什么、买到什么？ | 完整SKU与真实数量；文字规则按实际槽位，默认主图不加字 |
| 核心利益/卖点 | 为什么适合我？ | 一项主收益，真实操作、使用情境或细节 |
| 材质/设计/工艺细节 | 该理由如何成立？ | 可核实局部与资料；不由生成微距补造纹理或工艺 |
| Proof/机制 | 凭什么相信？ | 对应参数、报告范围或准确机制示意，不能伪装实测 |
| Scene/上身/多场景 | 我会如何使用？ | 合理动作、真实比例和活动，保持SKU一致 |
| Compare/选择 | 该选哪一款？ | 自有真实型号同口径数据；无数据不做贬损比较 |
| Spec/组合/安装/FAQ | 是否放得下、适配、包含什么、怎么用？ | 用户数据、到手清单、真实步骤与政策 |
| PDP/A+模块 | 如何形成连贯理解？ | 身份→重要利益→机制/证据→场景→选择，按请求删减 |

套图先分配主要购买主题和购买障碍，一个主题可由多个相关子卖点共同支撑，不理解为每张只能讲一个零件；也不固定“每张都放三卖点”。用户希望内容丰富时读 [内容充实与辅助视图](content-depth-and-supporting-visuals.md)，先合并弱细节，再配置主画面与有信息增量的辅助模块。同一point_id可由利益图和证据图分别展开，但第二次必须回答新问题或增加证据。只换场景重复同一口号不算信息增量。

## 每张制作卡增加以下映射

`图号 → 角色 → 主要买家疑问 → 主题下point_ids → claim_ids → 主画面与支撑模块/各自信息增量 → 补绘依据 → 逐字文案 → 阅读顺序 → 验收条件`

完整方案仍使用原制作卡，不以简表替代结构、比例、光影、字体、安全区和P0/P1要求。首张需在移动端一眼识别品类；后续特性图不必重复商品全名。

## 布局按证据选择

详细区域、字号层级、信息预算与手机适配读 [layout-design.md](layout-design.md)；整套排序与A+/详情节奏读 [image-set-planning.md](image-set-planning.md)，汇总到 [图序排版矩阵](../assets/image-sequence-layout-matrix.md)。

- 单主体大画面：整体外观、生活情境或一项清晰收益；文字不遮关键结构。
- 主图+一处放大：局部细节是关键证据；放大圈必须对应真实部位，线端准确。
- 左右/上下分区：操作前后或两个情境需要比较；先验证同条件与真实性，不生成假效果。
- 步骤条：有已确认操作顺序，强调用户如何完成任务；不虚构安装时长。
- 尺寸/参数图：信息本身承担选择，单位、引线与对象对应；不凭比例估数。
- 多场景拼图：不同活动对同一SKU有实际意义且移动端仍可读；空间不足拆图。
- 非对称编辑式：一侧商品、另一侧短信息；不能为了版式裁掉身份关键部件。

选择布局后再定风格。可选简约目录、温暖生活、技术参数、编辑杂志、明快对比、克制促销等方向；不是平台固定字体/配色。继承用户已有Campaign，Amazon不必用衬线，国内平台不必高饱和。

## 模特、角度与重试

只有穿戴/操作/比例理解需要人物时引入，避免无关人物分散商品注意力。复用已选模特参考及 model_id/文件、体型、发型、穿搭边界、机位与姿态；单图重试继续使用同一身份与Campaign，不随机换人。人物外观不证明真实尺码适配，搭配物不冒充套装。

允许基于现有照片支持的结构生成新机位、框架轮廓、去围布示意和细节图，不要求每个视图都有同机位实拍。缺背面参考时不把未知背面自动当作事实；不可见的连接、加强件和尺寸不能臆造。用户要求概念补全时明确标为概念，不能进入已验收的真实SKU图库；具体边界见内容充实模块。

## 动态提示词

读取身份事实、当前point_id、证据方法与所选布局，依原十段式规范构建自包含提示词。重复必要的身份与风格锁，不复制全部候选卖点。主图无字、附图/A+直接含精确文案的默认路线不改变。

文案和构图必须共同证明同一购买理由：标题强调兼容，画面就要对应真实接口/型号；标题谈空间选择，画面就要给准确尺寸或比例，而不是无关氛围。
