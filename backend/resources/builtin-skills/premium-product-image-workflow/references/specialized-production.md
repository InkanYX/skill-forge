# 专项制作

吸收 xianyu110/ecommerce-image-skills 的图型分工与 ecommerce-image-suite 的多图组织。所有图型共享身份、证据、风格版本与状态；不继承推广站、问卷和默认模型。

| 图型 | 制作与验收重点 |
|---|---|
| 白底主图 | 完整 SKU、纯白、无新字/道具；核对结构、边缘、白度与占比 |
| 场景 | 地点/时间/活动/镜头具体；核对尺度、光影、接地和包含物暗示 |
| 卖点/细节 | 一个购买问题与1–2个大细节；核对标签、引线、可见证据 |
| A+ | 按实际 Basic/Premium 槽位分工；核对桌面与手机可读性和像素 |
| 尺寸 | 用户数据与换算依据；示意不冒充测量 |
| 多角度 | 真实多视角参考；不认证未提供的隐藏结构 |
| 模特 | 保护版型、印花、Logo、材质和自然尺度 |
| 变体/批量 | 每图一个job，保存输入/输出/失败；只改指定表面 |
| 大促/社交 | 只用已确认价格/活动，不发明折扣、库存和评价 |
| 详情长图 | 分屏组织，按用户输入顺序拼接；检查每屏和整体 |

A+预设：header 970×600、banner 970×300、tile300 300×300、tile220 220×220、premium 1464×600、premium-mobile 600×450、brand-story 1464×625。这是工作预设，实际后台槽位/用户要求优先；不把静态表当完整现行规则，不强制所有图小于2MB。

手机端600×450按4:3画幅与排版基准使用，不默认把高清原生图压到该像素。桌面转手机先读 [手机端重排流程](mobile-adaptation.md)：独立重构布局，优先保留足够清晰的原生图及1200×900等同比例高清成品；仅在用户或后台要求精确600×450时另导出该尺寸。不要把普通resize、居中裁切或四周补边当成手机端适配。

## 导出

使用 `scripts/export_product_images.py`：

```
resize input.png --size 1464x600 --out output.png
grid a.png b.png --cols 2 --cell 732x300 --out preview.png
stitch screen-01.png screen-02.png --width 750 --out detail.png
```

resize 默认只接受近似同宽高比，等比处理并补极小余量；比例差异过大报错。需要留边显式 `--fit contain`；确需裁背景显式给 `--crop x0,y0,x1,y1` 并验不会裁商品/字。grid 等比留边，stitch 保留输入顺序，不默认中心裁或按文件名重排。新输出不覆盖，保存尺寸/哈希sidecar。保护原图与来源凭证，不宣称工具认证平台合规。
