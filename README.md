# Skill Forge

车棚、凉棚图片制作与团队经验复用工作台。

当前阶段：React + TypeScript + Vite 前端、Python 3.12 + FastAPI 后端。支持账号登录与成员权限、个人模型配置、PostgreSQL 持久化、文字生图、参考图编辑、套图制作、后台任务、产品资料、创作模板、只读技能包、后端 Agent 制作、作品收藏和经验备注。团队账号已提供基础角色与归属隔离；完整图片编辑器尚未实现。

## 环境

- Node.js 24.x（包含 npm）
- Python 3.12，由 uv 管理
- uv
- PostgreSQL 与 Docker 当前不是启动前置条件

## 接入现有 PostgreSQL

已安装 PostgreSQL 容器时，可在后端目录执行：

```powershell
cd D:\project\skill-forge\backend
uv sync --locked
uv run python -m app.database_setup bootstrap --container postgres
```

该命令读取指定容器的本机端口及连接凭据（不在终端显示密码），准备独立的 `skill_forge` 数据库，写入被忽略的 `backend/.env`，执行 Alembic 表结构迁移，再导入旧文件配置。原 JSON 和加密文件保留。已有 DATABASE_URL 时保留原配置；已有 `.env` 但没有数据库配置时不会覆盖文件，请自行按 `.env.example` 补充。

也可以自行在 `backend/.env` 填写 `DATABASE_URL`，随后执行：

```powershell
uv run python -m app.database_setup migrate
uv run python -m app.database_setup check
```

数据库结构由 `backend/migrations/` 管理。后续表结构升级使用 `uv run alembic upgrade head`；旧 JSON 导入只在 setup 命令中显式执行，重复导入不会覆盖数据库中已更新的记录（发现相同 ID 的冲突会取消导入）。应用启动不会自动修改表结构。

后端加载 `.env` 后需重启。`/api/health` 检查服务存活，`/api/system/status` 检查存储连接与配置表是否就绪。设置了数据库但连接失败时，配置 API 返回 503，不会静默切换到文件。

如果终端提示找不到 npm，先用 `node --version` 和 `npm --version` 检查。使用 nvm 时确认已启用 Node 24；安装后重新打开终端。项目不依赖全局 React/Vite。

另外打开一个 PowerShell：

```powershell
cd D:\project\skill-forge\frontend
npm ci

```

打开 http://127.0.0.1:5173 。后端运行时，首页应显示“后端连接正常”；后端关闭时显示连接失败，并可手动重新检查。

Vite 将 `/api` 代理到 `http://127.0.0.1:8000`。如需修改，复制 `frontend/.env.example` 为 `frontend/.env.local` 并调整 `API_PROXY_TARGET`，然后重启前端开发服务。生产环境应由反向代理转发 `/api`，Vite 开发代理只在开发模式工作。

所有开发服务仅监听本机地址。API Key 在“个人模型配置”页面输入，经本机后端加密保存；不返回原文，不写入浏览器 localStorage，不进入代码仓库。不要将密钥写入前端环境变量。

## 登录与成员权限

首次部署需要在后端目录创建第一个管理员（密码随机生成并只显示一次，首次登录后需修改）：

```powershell
cd D:\project\skill-forge\backend
uv run python -m app.auth init-admin --username admin
```

忘记管理员密码时可执行 `uv run python -m app.auth reset-admin-password --username admin`，会作废现有会话并取消其排队任务。管理员登录后在“成员管理”创建成员账号、停用成员或重置临时密码；成员首次登录需修改密码。

登录使用 HttpOnly、SameSite=Strict Cookie，默认有效期 12 小时；连续失败 7 次锁定 15 分钟。常规页面仅显示当前账号自己的内容，管理员也遵循该隔离规则；跨账号内容通过“团队共享”只读查看或复制，只有原作者可更新共享版本。改变密码、停用账号或重置密码会作废该账号会话并取消其仍未执行的排队任务。

“团队共享”默认开启。新项目先展示制作中信息，产品分析确认或首轮图片完成后自动发布首个完整快照；后续修改由作者手动“更新共享版本”。快照包含产品资料、方案历史、图片及参考输入、提示词、质检和反馈经验，不包含 API Key 或个人模型配置。作者可取消共享。复制后资料和图片独立保存，并标记原作者及共享版本，后续使用自己的模型配置，图需及提示词重新确认；经验作为待确认项导入，也可单独采用。取消共享不删除已有副本，第一版不支持共同编辑。升级数据库后可运行 `python -m app.team_sharing` 为已明确归属账号的历史项目补建默认共享。

图需编写分为“优化当前方案”（保留逐图主题与顺序）、“重新策划一套”（默认，重新安排卖点组合、图序与展示方式）和“按指定方向策划”（填写内容重点）。重新策划时不传入旧草稿及过往沟通作为修改底稿，只提供本人同产品最多 6 份、合计不超过 24000 字符的历史主题摘要用于对照。执行记录保存策划方式、方向、图位相似提醒与策划说明；文字对照不代表完整语义审核，也不会自动追加模型请求。Listing 主图职责单独保护，A+ 首模块参与正常对照。新图需另存为待确认版本，通过确认后才可继续提示词和生图，原图片保留。

## 个人模型配置

1. 页面中填写配置名称、公开 HTTPS Base URL 和 API Key。根地址会补 `/v1`，已有自定义路径会保留。首版连接测试仅支持 HTTPS 443 端口和公网 IPv4。
2. 点击“测试连接”检查服务商接口响应。后端带 Bearer 认证请求 `GET <Base URL>/models`，仅检查响应头，不下载、解析或更新模型列表；HTTP 200 仅代表此接口已响应，不代表具体模型已验证。404/405 会提示验证受限。
3. 点击独立的“读取模型”按钮获取模型列表，可搜索、多选，或手动添加模型 ID。两个操作分别显示结果，互不依赖，均不提交生成请求、上传图片或自动保存配置。服务商不支持模型列表时仍可手动配置。
4. 点击“保存配置”。刷新页面后点击已保存的配置可继续编辑。密钥留空表示保留旧值；改变地址时必须重新输入密钥。

页面需要登录后使用。首个管理员由部署时初始化，管理员可在“成员管理”创建成员账号并分配管理员/成员角色；成员只能编辑自己创建的内容，可查看或复制团队共享内容。仅监听本机地址，默认不应对外开放端口。未设置 DATABASE_URL 时保留文件存储模式；设置后配置保存到 PostgreSQL。连接测试不继承系统 HTTP 代理，不跟随重定向，拒绝本机和内网目标。

### 数据保存与备份

默认数据目录为 `backend/data/`，不随启动工作目录变化。可通过进程环境变量 `SKILL_FORGE_DATA_DIR` 设置绝对路径。

- `model-configs.json`：配置元数据及 Fernet 加密后的密钥。
- `config-encryption.key`：本机解密文件。必须与配置文件一起安全备份；丢失后已有密钥无法恢复。

数据库模式下 `model_configurations` 表保存配置和密文，继续使用原 `config-encryption.key`。备份时应包括数据库、加密文件和 `.env`，安全存放；只有数据库备份无法恢复解密能力。Docker 容器的数据卷也需要备份，删除数据卷会丢失数据库。

文件存储是数据库未就绪时的过渡实现，采用进程内锁和原子替换，当前仅支持一个后端进程。加密文件与数据均位于本机，不能防止拥有完整本机文件权限的人读取。请勿随意删除数据目录或只备份其中一个文件。

接口包括 `GET/POST /api/model-configs`、`PUT /api/model-configs/{id}`、`POST /api/model-configs/test`（仅连接结果）与 `POST /api/model-configs/models`（读取模型列表）。健康检查正常但配置接口返回 404 时，请重启后端加载新代码。

## 多图制作与后台 Worker

表结构更新后，执行 `uv run alembic upgrade head`。另外打开第三个终端运行：

```powershell
cd D:\project\skill-forge\backend
uv run python -m app.worker
```

页面分为“我的工作台”“多图制作”“个人模型配置”，分别通过 `#/`、`#/studio`、`#/settings` 访问，只渲染当前页面；菜单选中状态、顶部标题与浏览器前进后退同步。旧锚点链接仍可打开对应页面。

图片创作页内提供“自由创作”和“成套制作”两个切换项，共用标题和切换栏，仅下方内容随选择切换。同一次页面访问中，两种方式已填写的内容分别保留，隐藏内容不会出现在页面下方。选中方式写入网址（成套为 `#/studio?mode=set`），刷新可恢复方式；草稿仍仅保存在当前页面内。旧 `#/sets` 入口自动转入成套选项，`#/sets?set=<任务ID>` 继续用于查看套图结果。切换方式不会发起生成请求。

在“个人模型配置”保存服务商地址和密钥，同一份配置可保存最多 50 个模型并设置默认模型。读取服务商模型列表后可搜索、多选，也可手动逐个添加模型 ID。图片创作、套图制作和继续修改均展开显示“配置名称 · 模型 ID”，直接选择已保存的模型，无需重复填写 URL、密钥或模型名称。填写提示词、尺寸和生成数量（1–16 张，自由创作默认 1 张；选择模板后采用模板保存的数量，可手动调整），可附一张 PNG/JPEG/WebP 参考图（20 MB、2000 万像素以内）。点击生成才会创建真实调用，每张图片独立使用个人密钥调用服务商并消耗额度。

输出尺寸支持“自动（不指定尺寸）”、三种快捷尺寸和“自定义尺寸”。自定义填写像素宽高，例如 2000 × 2000；宽高须为正整数，总像素不超过本网站现有图片处理上限 2000 万。图片创作、套图每张图片、继续修改、模板默认尺寸使用同一设置。服务端将尺寸规范为 `宽x高` 后保存和发送；具体尺寸是否可用取决于所选服务商和模型。继续修改会带入来源作品的请求尺寸，套图确认清单与作品详情也会展示自定义尺寸。

“自动”继续使用内部值 `default`，请求服务商时省略 `size`，由其按默认规则处理，不代表固定分辨率或与参考图相同。指定尺寸表示生成请求的尺寸；网站不会为了匹配该值而缩放返回的图片。模板和历史任务的存储结构不变，无需数据库迁移。

已有环境执行 `uv run alembic upgrade head`，迁移 `0009_config_models` 会把原有单模型配置转为包含一个模型的列表，保留配置 ID、默认模型、密钥和历史任务；本次已迁移本机数据库。`model_name` 表示默认模型，`model_names` 表示可选模型列表。提交可携带已保存的 `model_name`，省略时使用默认模型；未保存的模型会被拒绝。修改默认模型、移除模型或修改密钥不影响已经创建的任务及其重复提交。

- 无参考图：`POST <Base URL>/images/generations`，JSON 请求，`n=1`。
- 有参考图：`POST <Base URL>/images/edits`，multipart 请求，字段 `image` 为经过方向校正和去除元数据的 PNG。
- 支持同步 Images 响应中的 `data[0].b64_json` 或公开 HTTPS `url`；下载图片不会携带服务商密钥，不跟随重定向。
- 当前只适配同步 OpenAI Images 协议；仅支持 Responses、Chat Completions 或私有异步协议的服务商，需要后续增加适配器。模型列表可读取不代表生图接口可用。

任务保存到 PostgreSQL `image_jobs` 表，图片位于 `backend/data/image-jobs/<任务ID>/`。刷新页面可恢复任务列表。Worker 每次领取一项任务，其他任务排队；首版先运行一个 Worker。上传素材和任务要求会发送给所选服务商。

多图通过 `POST /api/image-jobs/batch` 一次提交，批内任务在一个数据库事务中创建；每张图片分别生成、展示状态和下载，一张失败不影响其余图片。旧的单张接口仍保留兼容。

提交携带唯一 request_id，重发同一内容、数量与标识返回同一组任务。提交响应不明确时，页面保留标识并锁定输入；先核对列表，再决定重发或修改。任务保存了服务商和模型配置的加密快照，排队后修改配置不会改变原任务。终态任务清除其临时密钥密文。

执行成功后提供预览和 PNG 下载。超时、连接中断、返回不明或下载异常标为 `unknown`，不自动再次调用。Worker 异常退出时，运行任务在 15 分钟租约到期后由下一次队列检查标记未知，不自动重新排队；请先核对服务商记录。已排队且尚未执行的任务可在 Worker 重启后继续。

文件保存与数据库不构成同一事务；极端中断可能留下未关联文件或未知任务，原文件保留供核对。当前无自动清理或删除功能。数据库备份需要同时备份图片目录与加密文件。

测试使用模拟服务商和虚构密钥，不自动调用真实付费模型；可用 `SKILL_FORGE_TEST_POSTGRES=1` 显式启用本机 PostgreSQL 集成验证。

`npm run build` 包含 TypeScript 检查。前端产物位于 `frontend/dist`。Python 使用后端目录下的 `.venv`。依赖版本由 `package-lock.json` 和 `uv.lock` 锁定；首次准备环境需要联网下载依赖。

## 后续接入

### 业务工作台（已实现）

首页 `#/` 使用 `GET /api/workspace` 汇总真实业务数据，展示排队、生成中、累计完成和结果待确认数量。今日提交按任务创建时间统计，今日完成按成功任务的更新时间统计，日界线为北京时间（Asia/Shanghai），不受服务主机时区影响。

首页顶部提供“继续上次创作”：按账号在当前浏览器保存最近打开的产品、策划阶段或已提交生图任务，经过其他页面或刷新后可直接返回原位置，并显示最新方案进度。尚无访问记录时选择最近未完成的可编辑项目。未保存输入与未上传文件不在恢复范围内；入口只读取已有内容，不重新提交任务或调用模型。

首页显示最多 6 项进行中任务（生成中优先）、4 项需要关注的任务、6 张最近完成作品，以及最近维护的 4 份产品档案和模板。可直接取消排队任务、打开作品详情、携带产品或模板进入创作。状态卡片跳转生成记录并应用对应状态筛选。

未保存可用模型配置时展示配置引导，产品和模板明确为可选准备。首页每 15 秒自动刷新；读取失败时明确报错，若有旧数据则标注为上次数据，不把连接失败展示成零记录。技术连通检查移入底部折叠区，展开后才请求检查。仅聚合读取，不调用模型，不新增数据库表。

### 创作模板（已实现）

“创作模板”保存“怎么画”：模板名称、适用用途、画面要求、画面注意事项和默认出图参数。产品“是什么”（名称、SKU、颜色、尺寸、材质结构、结构红线）只保存在产品资料中；模板通过 `{{产品名称}}`、`{{颜色}}` 等占位符引用，不写死产品事实。制作方法、分析要点和检查要求直接写入画面要求；模板不再提供单独的 Skill 编辑区或 Skill 来源选择，新的文本技能请到技能库中使用“文本技能”导入。旧模板已保存的 Skill 内容继续参与生成。

为兼容已有数据，旧模板中已保存的 Skill 内容仍会合并进生成提示词并代入占位符；模板接口仍接受 `skill`、`skill_id`、`skill_revision` 字段，但前端不再提供编辑入口。历史任务、案例和 ZIP 导出中的模板快照保持完整。

旧版 `creative_skills`、`skill_revisions` 表及接口 `GET/POST /api/skills`、`PUT/GET /api/skills/{id}`、`GET /api/skills/{id}/versions`、`GET /api/skills/{id}/download` 仅保留用于旧模板兼容，读取和下载支持 `revision` 参数。旧版 Skill 接口、导入导出和模板同步不会调用模型。

### 只读技能包与版本（已实现）

`#/skills` 是统一的技能库页面，用于导入完整技能目录，也支持只包含一份文本的简单技能。每个技能包包含身份与一个或多个不可变版本；版本保存原始文件（只读）与确定性预编译快照 `compiled/context.md`。文件写入数据目录 `skills/`，数据库只保存元数据与文件清单（路径、分类、大小、SHA-256）。

- 导入格式在弹窗内三选一：ZIP 压缩包、文件夹、文本技能。优先识别 `SKILL.md`；没有标准入口且只有一份 Markdown／TXT 说明时自动使用该文档，多份说明时让用户选择入口，无需重新打包。文件限制默认折叠：压缩包 ≤20 MB、文件数 ≤1000、单文件 ≤5 MB。拒绝路径穿越、绝对路径、符号链接和不安全压缩包。
- **文本技能**：填写名称（必填）、说明（可选）和正文，或从 100 KB 以内的 Markdown / TXT 文件读入；文本最多 20000 字符。后端生成只读的 `SKILL.md` 并保存为普通的不可变技能包（`source=text`），因此同样拥有版本、预编译、归属与 Agent 能力。首次导入自动启用；内容未变化返回 `unchanged`；内容变化新增版本但不自动启用。
- 上传后确认要导入的技能，可直接修改名称和用途说明；不要求填写版本号或提供 `manifest.json`。同名入口按目录区分，同一批次的目标名称需不同。同名个人技能作为新版本导入，不覆盖旧版本。
- **新版本不会自动生效**：需在详情页手动“启用此版本”。历史任务与模板绑定记录始终锁定当时的 `skill_version_id`。
- 预编译快照保留作归档兼容，导入弹窗不再要求选择 `core`／`full`。正常策划流程通过只读文件工具按需读取原始资料，导入时填写的用途说明用于模型选择技能。
- 文件只读：页面可预览文本、下载任意文件核对，但不提供在线编辑。脚本与图片只存档，系统不会执行。
- **归属与可见性**：内置技能包（`source=builtin`，无 owner）全局共享；个人技能包（导入或 `fork`）归创建者私有，只有创建者能查看、启用并用于 Agent。管理员可只读查看全部成员的个人技能包用于排障，但不能代为启用。所有登录用户都可以导入或复制技能包；不同成员允许使用相同名称，内置名称保留且不能被个人技能覆盖。
- 内置两个技能包：`premium-product-image-workflow`（2.5.0，52 文件）与 `amazon-a-plus`（0.0.0，4 文件），后端启动时幂等写入，已存在同内容版本时跳过。

接口为 `GET /api/skill-packages`、`POST /api/skill-packages/import`、`POST /api/skill-packages/import/confirm`、`POST /api/skill-packages/import/text`、`GET /api/skill-packages/{id}/versions`、`POST /api/skill-packages/{id}/versions/{version_id}/activate`、`GET /api/skill-packages/{id}/versions/{version_id}/files`、`GET /api/skill-packages/{id}/versions/{version_id}/files/{path}`、`POST /api/skill-packages/{id}/fork`。迁移 `0015_skill_packages` 新增 `skill_packages`、`skill_versions`、`skill_files`、`agent_runs`、`agent_steps`、`agent_artifacts`，以及 `image_jobs.agent_run_id`、`image_configurations.vision_model_name`；`0016_private_skill_packages` 将技能包名称唯一性从全局改为“内置全局唯一 + 个人按 owner 唯一”。

### 技能驱动的图片创作（已实现）

`#/studio` 是统一入口，只保留自由创作与成套制作。新创作默认由模型从本人可用、已启用技能中选择并按需读取，也可指定多个必须加载的技能。提交时固定可用技能版本，先用已配置的文字模型整理完整提示词，通过预检后再调用图片接口。不再按技能名称自动搭配商品图或 A+ 技能。视觉模型可选，未配置时图片标为待人工审核；服务商能力验证仍为可选，不属于创作流程。

技能范围、固定版本、用途与原始要求保存在图片执行快照中；`input-prompt.txt`、`skill-context.md`、`skill-workflow.json`、实际 `prompt.txt` 与 `automatic-review.json` 保留制作依据。相同账号、素材、要求、技能版本及模型配置下可复用分析和策划，每张生成图仍单独检查。缓存不保存 API Key。读取日志保留模型实际取得的文件和范围。

每次制作保留独立执行轮次，同一次创作的修改归入一个任务。原始目标、本轮要求、父轮次和选定图片分开持久化；最新要求不会拼接后截断。可从生成记录打开 `#/studio?run={id}` 查看制作对话、图片版本和执行日志，并选择具体图片继续修改。旧 `#/agent` 链接兼容跳转到图片创作。

- 图片执行读取任务快照中的用户模型与可选请求参数，不按模型名、前缀或 Skill 示例固定模型、quality、size 或格式。空参数对象不额外发送参数。403、超时和结果不明均保存真实诊断，不自动切模型或重复提交。
- 工具集：`read_skill_file`、`write_prompt`、`generate_image`、`edit_image`、`view_image`、`finish`，外加确定性工具 `lint_prompt`、`count_copy`、`scan_copy`、`make_checklist`、`read_scenario`。技能内脚本不会被调用。
- 不引入 Codex 沙箱或任意脚本执行；AI 只负责运行时读技能与策划，压缩包解析全部由规则完成。
- 守卫：最大步数与出图次数、重复相同工具调用即停止、只能读取本技能版本目录内的文件、`edit_image`/`view_image` 只能操作本任务或本人生成的图片。Agent 生成的图片任务归属当前用户。
- 上传产品参考图后，配置好的视觉模型先分析实际图片，再将可见特征与不确定事项交给策划模型；省略 `use_reference` 时自动使用参考图，显式要求忽略参考图会在提交前停止。未配置视觉模型也可以制作，但必须保留参考图作为编辑输入并待人工审核。
- `view_image` 同时检查生成图、产品参考图（如有）、制作目标与实际提示词。视觉输入均转换为最长边 1280 的 JPEG 预览，原生图片不覆盖。质检覆盖结构、数量、比例、材质、颜色、文案、光影与制作要求；缺项、无法确认或非结构化回复不能判为通过。
- 后端根据实际图片与质检记录决定终态：`succeeded`（最终版本均自动质检通过）、`needs_review`（待人工审核）、`needs_changes`（质检需要修改）、`limit_reached`（执行达到上限）、`failed`、`unknown` 或 `cancelled`。未生成图片不能成功，已被新版本替代的旧图不计入最终版本质检。图片调用失败或结果不确定立即停止后续出图；取消状态不会被迟到的执行结果覆盖，尚未开始的子图片任务一并取消。
- 多轮工具执行的参考图分析、提示词检查与质检原始响应另存为 `agent-runs/{id}/records/` 下的 JSON；自动质检保存到 `execution_result.agent_review`，与人工检查 `execution_result.review` 分开保留。
- 任务创建只在后端执行；API Key 只在后端调用时使用，不进入模型上下文。本轮修改沿用固定的主技能版本和已有配套版本，使用选定原图继续编辑；待确认的付费调用会阻止重复提交。最多 30 轮、用户原始要求合计 32000 字符，超限明确拒绝提交，不静默截断。

现有 `/api/image-jobs`、`/batch`、`/sets` 创作接口统一接受可选的 `skill` JSON（`skill_id`、`version_id`）；省略时仍应用默认技能，修改任务则默认继承来源版本。`GET /api/agent/runs?latest=true` 按创作只返回最新轮次；`POST /api/agent/runs/{id}/rework` 接受 `instruction`、`source_job_id`。初次图片队列由 `StandardWorker` 按技能策划和质检；后续对话式修改由现有 `AgentWorker` 调用共用图片执行器。任务与步骤都归同一创作，生产无需额外进程。

迁移 `0017_creation_conversations` 增加会话、父轮次、来源图片与独立修改要求。旧 Agent 记录各自保留为独立创作，并将其图片归集；不会猜测或改写旧文本中的父子关系。迁移只添加字段与索引并更新归集标识，保留原始图片和记录。生成记录的任务状态反映最新轮执行结果，所有历史输出和日志继续保留。

### 取消排队任务（已实现）

创作结果、修改结果、作品详情及套图结果提供“取消排队”入口；套图可一次取消该套内全部排队任务（含排队中的修改版）。只有 `queued` 能转为 `cancelled`，已开始的 `running` 请求当前无法中止。页面区分这两种状态，不把服务商可能已开始的调用显示为“已取消”。

成功取消会清除该任务的临时密钥密文，保留要求、参考图和制作记录。Worker 跳过已取消任务，重发原提交标识仍返回已取消记录，不会恢复执行。取消与 Worker 领取使用数据库锁／条件更新协调；真实 PostgreSQL 并发测试在独立临时 schema 内执行并清理，不调用模型。生成记录支持按“已取消”筛选。

新增 `POST /api/image-jobs/{job_id}/cancel` 与 `POST /api/image-jobs/sets/{set_id}/cancel`，均使用 multipart `action=cancel`。单张重复取消成功返回原记录；已开始或已结束的其他状态返回 409。套图返回本次取消数量与各状态数量，重复取消不会影响已开始任务。此轮不新增表或字段，无需迁移；不会删除图片或自动重新生成。

### 批量导出（已实现）

新增 `POST /api/image-jobs/exports`，multipart 参数为 `job_ids`（UUID 数组的 JSON）或 `set_id` 二选一，以及 `include_records` 布尔值。文件缺失、未完成或数量超限会明确报错，不静默遗漏手动勾选的作品。后端用临时文件构建 ZIP，下载结束后关闭清理；不保存长期导出副本、不创建生图任务、不调用模型，本轮无需数据库迁移。前端保留下载链接，自动下载未开始时可再次点击。

### 生成记录（已实现）

### 创作模板与作品经验（已实现）

资料相关入口分为三处：“产品资料”只保存产品事实和原始素材；“创作模板”只保存制作方法，包含画面要求与画面注意事项；“生成记录”保存生成结果、修改记录、收藏和经验。在创作模板中新建制作方法，可从“凉棚 · 庭院场景”或“车棚 · 产品展示”示例开始，保存用途、画面要求、默认尺寸/数量及画面注意事项。用 `{{产品名称}}`、`{{颜色}}` 等占位符引用产品信息：选择产品后这些变量自动填入并只读，模板独有的 `{{场景}}` 等变量仍需手动填写；产品缺少对应字段时可在变量处临时补充。产品事实已在提示词中出现时，后端不再重复追加相同内容。制作方法直接写入画面要求，作为自然语言指令合并进请求，不执行代码或自动多步骤 Agent 流程。

### 标准图片接口（2026-11-23）

个人模型配置改为普通“连接＋模型列表”，无预填服务商或模型。模型 ID 可任意填写或从服务商读取，最多 100 个；无需设置文字、生图或质检等模型角色。当前模型用于直接调用和能力检查，图片创作可选择该连接已添加的其它模型。每个模型独立保存图片、文字与看图请求参数，空对象不发送额外参数；生图与编辑路径可配置。当前原生适配 OpenAI 兼容 Chat Completions／同步 Images 协议，其它服务商原生协议仍需对应适配器，不凭模型名称自动切换协议。

文本、图片理解、生图与编辑分别保存 supported／unsupported／error 能力证据。仅服务商明确返回不支持对应操作的错误代码才判为 unsupported；401／403／404／429、参数错误、超时等只表示调用问题，不据此禁用其它能力。能力检查仅在主动点击或实际调用时发生，保存连接不调用模型。提供普通文字调用入口，生图不支持不影响文字调用。变更连接地址或密钥清除旧能力证据，改变参数清除相应检查结果。

自动看图质检默认关闭，不需要额外配置质检模型；开启后使用当前模型，需要图片理解能力。质检由网站依据技能规范和本次制作要求组织，并非供应商内置的强制流程。纯图片模型缺少文字能力时，可直接使用原始要求与选定技能规则制作，不会强制要求另配文字模型；此路径会记录没有进行文字策划。旧角色配置保留用于历史兼容，新页面统一按模型列表使用。

新增迁移 `0018_generic_models`、`0019_model_registry`。旧用户原先的固定模型与参数仅作为旧配置数据保留，均可编辑；新连接没有这些默认值。新任务使用通用协议执行器，支持模型别名，不经过原脚本的 GPT Image 名称前缀限制。原始 image_gen.py 与历史 CLI 快照仍保留，未修改原脚本。

图片配置 `image_configurations` 只保存非密钥元数据；图片 API Key 仅由单 API 进程的内存保管，登录用户按账号隔离，未登录的本地开发页按浏览器 HttpOnly 会话隔离。不要使用多 API worker：各进程的内存密钥不共享。服务重启后需重新填写图片密钥，能力验证可选；未执行任务在密钥缺失时等待，配置修订改变后旧排队项被取消，不自动重复下单。

分别提供“测试连接”“验证图片生成”“验证参考图编辑”。连接测试只读 /models，不证明图片能力。两种图片验证都需要主动授权且可能计费；编辑验证要求上传实际参考文件。保存有效地址和运行时密钥后即可直接生成或编辑，能力验证为可选排查工具，不作为提交前置条件。模型 ID 不能证明底层模型版本或权限。本次仅通过模拟接口验证请求，未使用真实密钥或调用收费图片服务。

API 内的单线程任务执行器消费标准图片任务；独立旧 Worker 仅消费旧协议任务。生产启动 `uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log`，无需为标准任务另外启动 app.worker；本机开发启用 --reload 会在代码重载时丢失内存密钥。已有环境执行 `uv sync` 和 `uv run alembic upgrade head`（新增迁移 0012_standard_images）。

原始 CLI 在 `backend/vendor/imagegen/image_gen.py`，许可证保留，源脚本未修改。启动封装单独关闭 SDK 隐式重试并设置超时，调用次数由逐张重试逻辑管理；公网 HTTPS 请求保留证书校验、固定解析地址、不跟随重定向。明确失败按逐张上限处理，不自动降级模型、切服务商或将编辑改成无参考重画。超时／中断标记 unknown，先核对已有文件及服务商记录；当前未实现服务商异步任务查询。

每张任务目录保存 prompt.txt（UTF-8）、reference.png（如有）、result.png／result.jpg／result.webp（服务商原生字节）、preview.jpg（JPEG 预览）、execution.json（实际模型、参数、尺寸、格式与参考角色）。预览转换不改变原图，下载与 ZIP 文件扩展名跟随实际格式。UI 画幅用于构图，不固定原生 size；请求尺寸可在可选参数中指定。执行结果、自动及人工检查分别保存，继续修改不覆盖原图。

配置页为“模型连接”，包括连接信息、普通模型列表、当前模型的可选参数，以及独立的文字、看图、生图和编辑检查；不再按角色配置模型。输入校验返回 422 且不回显密钥；图片提交结果未知时保留原标识供核对和重发。

迁移 0013_shared_model_connection 增加文字模型 ID 和可选的已有连接引用，原配置与密钥不迁移、不覆盖。共用连接时地址和 API Key 仅填写一次，后端 resolve_text 复用运行时密钥；选择已有不同连接时沿用其原地址和密钥。只调整文字模型不会改变图片执行修订或清空图片检查结果。读取模型需主动点击，按所选连接访问 /models；不自动调用文字或图片模型。迁移 0015_skill_packages 增加 `vision_model_name`，供 Agent 的 `view_image` 使用；视觉模型留空时 Agent 只能以“待人工审核”结束。文字模型需支持 OpenAI 兼容的 tool calling，视觉模型需支持图片输入，否则 Agent 会明确失败或降级，不会静默跳过质检。

### A+ 默认画幅与图片版本

提示词阶段的参考图由程序固定继承已确认图需，包括原始顺序；模型只输出图片标识与提示词正文。生成结果及手动保存均以已确认图需为准，不采纳模型新增、遗漏或替换的参考图。更换参考图需先修改并重新确认图需，旧提示词和生成记录保留。

A+ 策划默认使用 Premium A+ 桌面端 1464×600；用户明确选择普通模块或手机端时使用相应画幅，首张可为带文案的场景英雄图。Listing 商品套图首张主图只完整展示商品，无新增标题、卖点、图标或装饰排版，产品自带标识保留，背景依用户确认且不强制白底；附图与 A+ 才应用文案排版规则。优先使用方案明确选择的图型，未指定时依据制作目标区分；主图文案冲突在图需、提示词确认和生图提交前检查，旧方案需先修订并重新确认，不能静默改写已确认提示词。内置商品图技能 2.5.3 与 A+ 技能 0.0.1 包含这些规则；已有安装需在技能库启用新版本，已有方案继续保留锁定快照。请求画幅和模型实际返回的原生像素分别记录。

同一方案每次提交图片独立显示为一版，默认查看最新版本，可切换旧版。批次依据持久化的 job_ids 区分，提示词、图片、日志和导出均限于所选批次；取消排队也仅作用于当前批次。历史图片保留。

迁移 `0023_image_trash` 添加可恢复删除标记。图片卡片提供删除确认与撤销；已删除图片从作品、套图、任务图片和方案图片列表移除，原文件与溯源记录保留，任务壳记录仍可追溯。排队、运行中及结果待确认的图片不能删除。接口为 `DELETE /api/image-jobs/{id}` 和 `POST /api/image-jobs/{id}/restore`（multipart 字段 `action=restore`），均检查编辑权限；删除与恢复重复调用安全，不改变原生成完成时间。

### A+ 手机版、失败补试与完整案例

完成整版 1464×600 桌面 A+ 后，在方案的图片制作区域选择批次，点击“一键制作整套手机版”。确认后创建独立手机方案，以桌面原图及产品素材作为真实编辑参考，按 1200×900（4:3）重新组织场景和文案；不是裁切或拉伸。每张手机版会产生新的图片调用，桌面原图保留。需要同一服务商连接下相应模型的参考图编辑能力证据。

标准图片调用明确失败时，每张最多尝试 3 次（首次加两次补试），逐次记录结果；单张失败不取消同批次后续图片。401／403 不自动重复调用该张；超时或结果不确定、目录已有返回图片时不重复下单，应先核对文件和服务商记录。

失败或已取消的图片卡片及详情提供“重试生图（最多 3 次）”。点击后新建单张任务，沿用原模型、接口、参数、完整提示词及真实参考图；方案内重试留在原版本的原图位，不增加版本或打乱图号。原失败记录保留在该版本运行日志中，图片计数、导出和手机版适配使用当前结果；旧的独立重试批次也按来源合回原版本。提交标识防止重复点击，已有排队或执行中的重试会直接复用，已有结果待确认的重试则要求先核对计费。重启后需先重新填写原服务商运行时密钥；连接地址或接口路径变化时拒绝自动换接口重试。

结果待确认（`unknown`）的图片提供“核对后重新生成”。用户须勾选已核对服务商任务与计费、未找到可用图片且接受新费用，再确认提交；后端要求 multipart `provider_checked=true` 并在新记录保存确认人、时间及来源。原记录和参考图保留，目录已有返回图片或原图已有结果待确认的重试时仍阻止重复下单。新任务再次超时仍停止，需重新核对后从该次记录操作，不自动连发。

已有图片“继续修改”先由文本模型理解用户指出的问题、目标与保留项，再由视觉模型实际检查来源成图（有原始产品身份参考时对照），最后由文本模型读取适用 Skill、综合观察与已确认资料，输出修改步骤、保留项、不确定项和 `Edit only ...` 编辑提示词，再将来源原图提交给图片编辑接口。此分析不依赖是否开启生成后的自动质检；视觉/文本失败、结构化方案不完整或需要补充时，不降级为直接生图。结果卡片和图片详情可查看分析记录与实际提示词；记录保存为 UTF-8 `revision-analysis.json`、`prompt.txt`，图片与原记录保留。失败生图的手动重试复用已完成分析及原提示词，不重复规划。

图片制作区域可将完成流程保存为独立案例，侧栏“完整案例”提供展示、搜索、下载和参考复用。归档包含原始资料（含 PDF）、产品分析、图需、风格、完整提示词、参考角色与文件、原生图片和预览、实际尺寸、技能版本与读取日志、质检及人工反馈；关联的桌面版和手机版一并保存。案例冻结后不随原方案或图片删除而变化，单个案例素材总量上限 500MB，ZIP 导出校验文件哈希。

复用案例时必须选择已确认分析的目标产品，新方案使用目标产品事实与素材，只借鉴案例的风格、组织方式及人工确认经验，并在后续生成前继续确认图需和提示词。选中的案例风格参考图可能随之后授权的生图请求发给已配置服务商。经验复用不会自动训练或修改基础模型；人工确认的总结用于积累可追溯的作图经验。

已有环境执行 `uv run alembic upgrade head`（新增 `0024_workflow_cases`），重启 API 后重新填写仅保存在内存中的模型密钥。功能测试使用模拟接口，不产生真实付费图片请求。

### 视觉风格选项

图片策划的新建页和方案详情提供“整套风格与排版”：沉浸场景、品牌杂志、电影叙事、科技解析、极简高端、高信息说明，以及 AI 根据产品推荐。构图示意仅解释布局，不代表实际成图。排版变化程度、文字密度和图形配色分别设置，补充风格及实际参考图继续可用；默认不指定背景色，也不改变商品本色。

预设源为 `backend/app/visual_styles.py`，接口为 `GET /api/creation-projects/visual-styles`。保存时冻结选择、规范全文、验收依据与版本；更新目录不替换旧方案快照。风格是技能工作流的视觉输入，不能替代技能读取或增加产品事实。AI 在图需中说明整套视觉方向与推荐理由，并逐张编写构图、文字层级和相邻图差异，用户可编辑确认后再进入提示词和生图。

修改预设、变化程度、文字密度、配色或补充风格后，图需与提示词重新确认，产品分析、历史文档和原图保留。旧方案未选择预设时保留已有自由风格，不自动改写。图需对缺失或完全相同的构图说明给出机械提醒，不视为视觉验收。开启原有自动质检时，锁定的视觉规范会随单图检查传入；整套构图差异仍需人工结合全套检查。案例归档与新产品复用、桌面转手机版继续保留对应视觉规范；本次无需数据库迁移。

### 人工评价与作图经验积累

图片详情可记录采用、返工或弃用，分别为产品保真、构图、文字排版、场景和风格评分；也可选择同产品或修改链中的本人历史作品，说明版本偏好。保存时冻结对比提示词、修改要求、评分差异与反馈版本，原图保留。评分变化仅表示这次人工评价，不代表模型整体质量提升。

产品详情可选择反馈，使用已配置文字模型整理经验建议；此操作会调用文字接口，输入包含反馈和提示词，不自动上传图片。建议必须人工检查并确认后才进入后续策划。默认限当前产品；用于同品类或通用范围时需填写范围并明确确认可跨产品复用。来源反馈修改后，旧经验暂停匹配，需重新整理和确认。

侧栏“作图经验”汇总本人经验，可搜索、筛选并返回来源产品编辑。图片策划提供经验开关、品类、图片类型、设备及逐条排除；预览使用已保存设置，修改后需保存并重新确认图需和提示词。匹配优先当前产品，再考虑本人确认的同品类与通用规则；来源、版本、命中原因随策划执行冻结，旧方案不随经验库变更。

产品页和经验库支持导出学习数据 JSON，包含评价、版本偏好、提示词、参考角色、技能与风格快照及经验来源；完整图片和原始资料通过“完整案例”归档导出。学习 JSON 用于整理和审查，并非可直接提交的微调训练集，弃用和返工作品不会标记为正例。这一机制通过检索确认经验改善后续输入，不自动训练基础模型；保存、匹配、导出均不调用付费模型。本次不新增数据库迁移。
