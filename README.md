# Skill Forge

车棚、凉棚图片制作与团队经验复用工作台。

当前阶段：React + TypeScript + Vite 前端、Python 3.12 + FastAPI 后端。支持个人模型配置、PostgreSQL 持久化、文字生图、参考图编辑、套图制作、后台任务、产品资料、创作模板与 Skill、作品收藏和经验备注。当前为本机单人使用，团队账号与完整图片编辑器尚未实现。

## 环境

- Node.js 24.x（包含 npm）
- Python 3.12，由 uv 管理
- uv
- PostgreSQL 与 Docker 当前不是启动前置条件

## 接入现有 PostgreSQL

已安装 PostgreSQL 容器时，可在后端目录执行：

```powershell
cd D:\project\skill-forge\backend
uv sync --locked
uv run python -m app.database_setup bootstrap --container postgres
```

该命令读取指定容器的本机端口及连接凭据（不在终端显示密码），准备独立的 `skill_forge` 数据库，写入被忽略的 `backend/.env`，执行 Alembic 表结构迁移，再导入旧文件配置。原 JSON 和加密文件保留。已有 DATABASE_URL 时保留原配置；已有 `.env` 但没有数据库配置时不会覆盖文件，请自行按 `.env.example` 补充。

也可以自行在 `backend/.env` 填写 `DATABASE_URL`，随后执行：

```powershell
uv run python -m app.database_setup migrate
uv run python -m app.database_setup check
```

数据库结构由 `backend/migrations/` 管理。后续表结构升级使用 `uv run alembic upgrade head`；旧 JSON 导入只在 setup 命令中显式执行，重复导入不会覆盖数据库中已更新的记录（发现相同 ID 的冲突会取消导入）。应用启动不会自动修改表结构。

后端加载 `.env` 后需重启。`/api/health` 检查服务存活，`/api/system/status` 检查存储连接与配置表是否就绪。设置了数据库但连接失败时，配置 API 返回 503，不会静默切换到文件。

如果终端提示找不到 npm，先用 `node --version` 和 `npm --version` 检查。使用 nvm 时确认已启用 Node 24；安装后重新打开终端。项目不依赖全局 React/Vite。

另外打开一个 PowerShell：

```powershell

```

打开 http://127.0.0.1:5173 。后端运行时，首页应显示“后端连接正常”；后端关闭时显示连接失败，并可手动重新检查。

Vite 将 `/api` 代理到 `http://127.0.0.1:8000`。如需修改，复制 `frontend/.env.example` 为 `frontend/.env.local` 并调整 `API_PROXY_TARGET`，然后重启前端开发服务。生产环境应由反向代理转发 `/api`，Vite 开发代理只在开发模式工作。

## 个人模型配置

1. 页面中填写配置名称、公开 HTTPS Base URL 和 API Key。根地址会补 `/v1`，已有自定义路径会保留。首版连接测试仅支持 HTTPS 443 端口和公网 IPv4。
2. 点击“测试连接”检查服务商接口响应。后端带 Bearer 认证请求 `GET <Base URL>/models`，仅检查响应头，不下载、解析或更新模型列表；HTTP 200 仅代表此接口已响应，不代表具体模型已验证。404/405 会提示验证受限。
3. 点击独立的“读取模型”按钮获取模型列表，可搜索、多选，或手动添加模型 ID。两个操作分别显示结果，互不依赖，均不提交生成请求、上传图片或自动保存配置。服务商不支持模型列表时仍可手动配置。
4. 点击“保存配置”。刷新页面后点击已保存的配置可继续编辑。密钥留空表示保留旧值；改变地址时必须重新输入密钥。

当前为**本机单用户开发模式**，尚无团队账号隔离，不应对外开放端口。未设置 DATABASE_URL 时保留文件存储模式；设置后配置保存到 PostgreSQL。连接测试不继承系统 HTTP 代理，不跟随重定向，拒绝本机和内网目标。

### 数据保存与备份

默认数据目录为 `backend/data/`，不随启动工作目录变化。可通过进程环境变量 `SKILL_FORGE_DATA_DIR` 设置绝对路径。

- `model-configs.json`：配置元数据及 Fernet 加密后的密钥。
- `config-encryption.key`：本机解密文件。必须与配置文件一起安全备份；丢失后已有密钥无法恢复。

数据库模式下 `model_configurations` 表保存配置和密文，继续使用原 `config-encryption.key`。备份时应包括数据库、加密文件和 `.env`，安全存放；只有数据库备份无法恢复解密能力。Docker 容器的数据卷也需要备份，删除数据卷会丢失数据库。

文件存储是数据库未就绪时的过渡实现，采用进程内锁和原子替换，当前仅支持一个后端进程。加密文件与数据均位于本机，不能防止拥有完整本机文件权限的人读取。后续迁移至 PostgreSQL 时保留接口契约，并补充账号隔离。请勿随意删除数据目录或只备份其中一个文件。

接口包括 `GET/POST /api/model-configs`、`PUT /api/model-configs/{id}`、`POST /api/model-configs/test`（仅连接结果）与 `POST /api/model-configs/models`（读取模型列表）。健康检查正常但配置接口返回 404 时，请重启后端加载新代码。

## 多图制作与后台 Worker

表结构更新后，执行 `uv run alembic upgrade head`。另外打开第三个终端运行：

```powershell
cd D:\project\skill-forge\backend
uv run python -m app.worker
```

页面分为“我的工作台”“多图制作”“个人模型配置”，分别通过 `#/`、`#/studio`、`#/settings` 访问，只渲染当前页面；菜单选中状态、顶部标题与浏览器前进后退同步。旧锚点链接仍可打开对应页面。

图片创作页内提供“自由创作”和“成套制作”两个切换项，共用标题和切换栏，仅下方内容随选择切换。同一次页面访问中，两种方式已填写的内容分别保留，隐藏内容不会出现在页面下方。选中方式写入网址（成套为 `#/studio?mode=set`），刷新可恢复方式；草稿仍仅保存在当前页面内。旧 `#/sets` 入口自动转入成套选项，`#/sets?set=<任务ID>` 继续用于查看套图结果。切换方式不会发起生成请求。

在“个人模型配置”保存服务商地址和密钥，同一份配置可保存最多 50 个模型并设置默认模型。读取服务商模型列表后可搜索、多选，也可手动逐个添加模型 ID。图片创作、套图制作和继续修改均展开显示“配置名称 · 模型 ID”，直接选择已保存的模型，无需重复填写 URL、密钥或模型名称。填写提示词、尺寸和生成数量（1–8 张，默认 4 张），可附一张 PNG/JPEG/WebP 参考图（20 MB、2000 万像素以内）。点击生成才会创建真实调用，每张图片独立使用个人密钥调用服务商并消耗额度。

输出尺寸支持“自动（不指定尺寸）”、三种快捷尺寸和“自定义尺寸”。自定义填写像素宽高，例如 2000 × 2000；宽高须为正整数，总像素不超过本网站现有图片处理上限 2000 万。图片创作、套图每张图片、继续修改、模板默认尺寸使用同一设置。服务端将尺寸规范为 `宽x高` 后保存和发送；具体尺寸是否可用取决于所选服务商和模型。继续修改会带入来源作品的请求尺寸，套图确认清单与作品详情也会展示自定义尺寸。

“自动”继续使用内部值 `default`，请求服务商时省略 `size`，由其按默认规则处理，不代表固定分辨率或与参考图相同。指定尺寸表示生成请求的尺寸；网站不会为了匹配该值而缩放返回的图片。模板和历史任务的存储结构不变，无需数据库迁移。

已有环境执行 `uv run alembic upgrade head`，迁移 `0009_config_models` 会把原有单模型配置转为包含一个模型的列表，保留配置 ID、默认模型、密钥和历史任务；本次已迁移本机数据库。`model_name` 表示默认模型，`model_names` 表示可选模型列表。提交可携带已保存的 `model_name`，省略时使用默认模型；未保存的模型会被拒绝。修改默认模型、移除模型或修改密钥不影响已经创建的任务及其重复提交。

- 无参考图：`POST <Base URL>/images/generations`，JSON 请求，`n=1`。
- 有参考图：`POST <Base URL>/images/edits`，multipart 请求，字段 `image` 为经过方向校正和去除元数据的 PNG。
- 支持同步 Images 响应中的 `data[0].b64_json` 或公开 HTTPS `url`；下载图片不会携带服务商密钥，不跟随重定向。
- 当前只适配同步 OpenAI Images 协议；仅支持 Responses、Chat Completions 或私有异步协议的服务商，需要后续增加适配器。模型列表可读取不代表生图接口可用。

任务保存到 PostgreSQL `image_jobs` 表，图片位于 `backend/data/image-jobs/<任务ID>/`。刷新页面可恢复任务列表。Worker 每次领取一项任务，其他任务排队；首版先运行一个 Worker。上传素材和任务要求会发送给所选服务商。

多图通过 `POST /api/image-jobs/batch` 一次提交，批内任务在一个数据库事务中创建；每张图片分别生成、展示状态和下载，一张失败不影响其余图片。旧的单张接口仍保留兼容。

提交携带唯一 request_id，重发同一内容、数量与标识返回同一组任务。提交响应不明确时，页面保留标识并锁定输入；先核对列表，再决定重发或修改。任务保存了服务商和模型配置的加密快照，排队后修改配置不会改变原任务。终态任务清除其临时密钥密文。

执行成功后提供预览和 PNG 下载。超时、连接中断、返回不明或下载异常标为 `unknown`，不自动再次调用。Worker 异常退出时，运行任务在 15 分钟租约到期后由下一次队列检查标记未知，不自动重新排队；请先核对服务商记录。已排队且尚未执行的任务可在 Worker 重启后继续。

文件保存与数据库不构成同一事务；极端中断可能留下未关联文件或未知任务，原文件保留供核对。当前无自动清理或删除功能。数据库备份需要同时备份图片目录与加密文件。

测试使用模拟服务商和虚构密钥，不自动调用真实付费模型；可用 `SKILL_FORGE_TEST_POSTGRES=1` 显式启用本机 PostgreSQL 集成验证。

`npm run build` 包含 TypeScript 检查。前端产物位于 `frontend/dist`。Python 使用后端目录下的 `.venv`。依赖版本由 `package-lock.json` 和 `uv.lock` 锁定；首次准备环境需要联网下载依赖。

## 后续接入

### 业务工作台（已实现）

首页 `#/` 使用 `GET /api/workspace` 汇总真实业务数据，展示排队、生成中、累计完成和结果待确认数量。今日提交按任务创建时间统计，今日完成按成功任务的更新时间统计，日界线为北京时间（Asia/Shanghai），不受服务主机时区影响。

首页显示最多 6 项进行中任务（生成中优先）、4 项需要关注的任务、6 张最近完成作品，以及最近维护的 4 份产品档案和模板。可直接取消排队任务、打开作品详情、携带产品或模板进入创作。状态卡片跳转生成记录并应用对应状态筛选。

未保存可用模型配置时展示配置引导，产品和模板明确为可选准备。首页每 15 秒自动刷新；读取失败时明确报错，若有旧数据则标注为上次数据，不把连接失败展示成零记录。技术连通检查移入底部折叠区，展开后才请求检查。仅聚合读取，不调用模型，不新增数据库表。

### 独立 Skill 管理（已实现）

在“创作模板”页切换到“Skill 管理”（`#/skills`）。Skill 可单独命名、填写用途、粘贴内容或导入单个 Markdown/TXT 文件（100 KB、20000 字符以内），保存后可由多个模板复用。新建使用弹窗，列表支持名称、用途和内容搜索；可查看最近 100 个版本并导出指定版本的原始内容为 Markdown。内容仅作为文本保存和使用，不执行代码、不自动执行多步骤流程。

创作模板可选择关联 Skill 库，或继续在本模板内直接编写。关联时由后端读取指定的不可变版本，忽略客户端对该版本内容的改写；模板记录保存 Skill ID、名称、版本及完整内容。Skill 发布新版不会自动改变模板，模板页刷新 Skill 列表后可点击“同步最新版到草稿”，再次保存模板才生效。也可选择“仅在本模板内编写”，保留已复制内容并解除关联。

历史任务、案例和 ZIP 导出中的模板快照均保留当时的 Skill 版本与内容。编辑 Skill 使用版本冲突检查，无内容变化时不新增版本；旧模板没有 Skill 库关联时按原方式使用。

新增 `creative_skills`、`skill_revisions` 表，已有环境执行 `uv run alembic upgrade head`；本次已迁移本机数据库。接口为 `GET/POST /api/skills`、`PUT/GET /api/skills/{id}`、`GET /api/skills/{id}/versions`、`GET /api/skills/{id}/download`，读取和下载支持 `revision` 参数。Skill 管理、导入导出和模板同步不会调用模型。

### 取消排队任务（已实现）

创作结果、修改结果、作品详情及套图结果提供“取消排队”入口；套图可一次取消该套内全部排队任务（含排队中的修改版）。只有 `queued` 能转为 `cancelled`，已开始的 `running` 请求当前无法中止。页面区分这两种状态，不把服务商可能已开始的调用显示为“已取消”。

成功取消会清除该任务的临时密钥密文，保留要求、参考图和制作记录。Worker 跳过已取消任务，重发原提交标识仍返回已取消记录，不会恢复执行。取消与 Worker 领取使用数据库锁／条件更新协调；真实 PostgreSQL 并发测试在独立临时 schema 内执行并清理，不调用模型。生成记录支持按“已取消”筛选。

新增 `POST /api/image-jobs/{job_id}/cancel` 与 `POST /api/image-jobs/sets/{set_id}/cancel`，均使用 multipart `action=cancel`。单张重复取消成功返回原记录；已开始或已结束的其他状态返回 409。套图返回本次取消数量与各状态数量，重复取消不会影响已开始任务。此轮不新增表或字段，无需迁移；不会删除图片或自动重新生成。

### 批量导出（已实现）

生成记录支持勾选已完成图片、选择本页已完成图片、跨页保留选择及清空选择；点击“导出选中图片”下载 ZIP。套图结果页可直接导出整套已完成图片（含修改版），排队或失败项不会被套图导出选入。导出每次最多 50 张，图片原始大小合计不超过 200 MB，超限时请到生成记录分批选择。

ZIP 中 `images/` 保存原始 PNG，按编号、SKU、图片用途与任务标识命名，避免重名和无效路径。默认勾选“附制作记录”，添加 UTF-8 `manifest.json` 和带 BOM 的 `制作记录.csv`，含制作要求、产品/模板快照、修改及套图关系、案例经验。CSV 防止用户内容被当作公式执行。可取消勾选，仅导出图片。不会包含模型密钥、服务商地址或加密文件。

新增 `POST /api/image-jobs/exports`，multipart 参数为 `job_ids`（UUID 数组的 JSON）或 `set_id` 二选一，以及 `include_records` 布尔值。文件缺失、未完成或数量超限会明确报错，不静默遗漏手动勾选的作品。后端用临时文件构建 ZIP，下载结束后关闭清理；不保存长期导出副本、不创建生图任务、不调用模型，本轮无需数据库迁移。前端保留下载链接，自动下载未开始时可再次点击。

### 成套图片制作（已实现）

“图片创作”提供自由创作与成套制作两个入口，成套制作地址为 `#/sets`。默认六张用途清单（主体展示、庭院场景、结构细节、尺寸说明、使用场景、材质近景），每张有独立要求和尺寸，可增删、调整顺序，最多 8 张。默认清单仅作为可编辑起点，不保证上架规范或产品参数准确，生成后需人工检查。

整套共用一个模型配置、产品资料、单张参考图和可选创作模板／Skill；公共要求与单张要求分别保存到每张任务的最终提示词。点击“检查生成清单”只预览安排；再次“确认生成”后才创建真实任务并使用服务商额度。整套任务在一个数据库事务中写入，重复提交相同标识返回原清单，数量、顺序或内容改变会被拒绝。

提交后进入 `#/sets?set=<提交标识>` 查看进度，刷新后仍能恢复。每张结果可下载、进入作品详情或继续修改。修改版保留原套图和用途关联；作品详情提供“查看整套图片”入口，生成记录支持按套图名称和用途关键词搜索。

新增 `POST /api/image-jobs/sets`（multipart，`plan` 为套图名称及单张要求的 JSON）与 `GET /api/image-jobs/sets/{set_id}`，后者最多返回 200 项原图和修改版，并标记是否还有更多。已有环境执行 `uv run alembic upgrade head`，本次已迁移本机数据库。生成仍是逐张同步 Images 请求，不保证整套风格自动一致，不执行自动质量审核。

### 基于作品继续修改（已实现）

在图片创作结果或作品详情点击“继续修改”，打开 `#/edit?source=<任务ID>`。来源必须是已完成且本机图片文件可用的作品。填写本次修改要求，选择当前保存的模型配置、尺寸和数量（默认 1 张），手动提交后才调用服务商的 Images 编辑接口。修改会产生新的任务和图片，原图不会被覆盖。

新任务使用来源图片的独立拷贝作为参考，并沿用来源任务的产品和模板快照；制作指令使用本次修改要求及原产品资料，不重新执行原模板或 Skill。原模板记录仅用于追溯。每张新版本保存 `parent_job_id`、`edit_instruction`，已终态任务清除临时密钥后，继续修改依然使用当前模型配置中的密钥。

作品详情支持修改前后对比，修改记录可跳转到来源或分支作品。`GET /api/image-jobs/{job_id}/versions` 返回最多 50 个来源记录及最近 20 个直接修改任务，并标明是否还有更多记录。继续修改仍保留重复提交保护和未知结果不自动重试机制；读取记录、预览、跳转不会调用模型。

已有环境更新后执行 `uv run alembic upgrade head`；本次已迁移本机数据库。测试使用虚构密钥和模拟生成结果，真实服务商仍需提供兼容的同步 Images 编辑接口。当前是整图自然语言修改，不含蒙版、涂抹或像素级编辑工具。

### 生成记录（已实现）

访问 `#/library` 集中浏览全部生成记录，默认显示全部任务状态，每页 12 项，包含排队、生成中、已完成、失败及修改记录。关键词、产品、模板、任务状态、收藏和经验备注集中在“筛选记录”区域，修改条件后统一点击末尾的“查询”生效；重置恢复全部记录。查询使用任务保存时的资料快照。旧的创作页“最近任务”仍保留，并提供“查看全部作品”入口。

点击图片或任务卡片打开详情弹窗，查看大图、参考图、请求尺寸、模型以及当时的产品和模板版本，支持 PNG 下载。排队/生成中的详情自动更新，列表每 10 秒刷新。已完成作品可以单独收藏，也可以填写或更新经验备注；支持“仅收藏”“有经验备注”筛选，可组合使用，搜索同时覆盖经验标题、内容和问题记录。

`GET /api/image-jobs/library` 支持 `page`、`page_size`（最大 48）、`status`、`q`、`product_id`、`template_id`、`favorite` 和 `has_notes` 参数。`POST /api/image-jobs/{job_id}/favorite` 使用 multipart 字段 `favorite` 明确设置收藏状态，重复请求不会反向切换，不修改生成完成时间。已有环境运行 `uv run alembic upgrade head` 添加 `is_favorite` 字段；本次开发已迁移本机数据库。整理作品不触发模型调用。

### 创作模板与作品经验（已实现）

资料相关入口分为三处：“产品资料”保存产品事实和原始素材；“创作模板”保存制作方法，内部管理 Skill；“生成记录”保存生成结果、修改记录、收藏和经验。在创作模板中新建制作方法，可从“凉棚 · 庭院场景”或“车棚 · 产品展示”示例开始，保存用途、画面要求、默认尺寸/数量及注意事项。用 `{{产品名称}}`、`{{颜色}}` 等占位符定义产品信息，创作时自动生成必填项。Skill 支持粘贴或导入 Markdown/TXT（100 KB 内、20000 字符内），作为自然语言指令合并进请求，不执行代码或自动多步骤 Agent 流程。

保存模板后点击“使用此模板”，在图片创作页填写产品信息，选择自己的模型配置并上传可选参考图。服务端渲染最终制作要求，保存完整模板版本、Skill、填写值与补充要求到每张任务的 `template_snapshot`。模板修改使用版本冲突检查，历史任务和案例始终保留当时的版本；重复提交仍复用原有任务。

生成成功后，可在结果区或作品详情填写“经验备注”，只需一句经验，标题和问题记录可选。原案例数据继续使用 `creative_cases` 保存，已有标题、经验、问题均可读取和修改；不复制图片，每张图片只保存一份经验。兼容原有 `/api/cases` 接口，新增 `GET /api/cases/{job_id}` 按作品读取备注（没有备注返回 null）。原 `#/cases` 地址自动转到生成记录的经验筛选。当前仍是本机单人阶段，未提供团队账号权限。

### 产品资料与素材（已实现）

进入 `#/products` 按 SKU 新建产品，填写品类、名称、含单位的尺寸、颜色、已确认的材质/结构与制作注意事项。SKU 去除首尾空白并转为大写，同一 SKU 只能保存一份产品。资料修改采用版本检查，避免覆盖其他修改。

保存产品后可分批上传产品实拍、结构细节、尺寸图或其他图片。每次最多选 8 张，每张最多 20 MB、2000 万像素，支持 PNG/JPEG/WebP；服务端校验并转换为去除元数据的 PNG，保存在 `backend/data/products/`。素材文件不覆盖已有内容，重复同一上传标识返回原素材。上传不会调用模型。

“用此产品创作”会打开图片创作页。选择产品后，名称、颜色、尺寸会带入模板的同名变量，也可以人工调整；模板中的场景等其他信息仍需填写。可选一张产品素材作为参考图，或临时上传一张，二者互斥。提交时产品资料与参考素材写入任务快照，参考图复制到任务目录。后续修改资料不会影响历史任务与案例；旧版本未提交的草稿会要求重新选择产品。
