# 图片并发与维护恢复

标准生图使用 6 个工作线程。所有标准/旧版任务共用数据库调度规则：全局最多 6 张处于执行状态，每个账号最多 2 张；其他图片保留原任务、版本与顺序，自动等候名额。某账号名额已满不会阻止其他账号领取任务。

PostgreSQL 通过事务级 advisory lock 串行领取名额，锁在调用服务商之前释放，保证多个线程或进程不会同时超额领取。SQLite 测试通过写事务验证同样的规则。超时任务仍标为结果待确认，不自动重发；原有每张最多 3 次的明确失败重试规则保留。

维护时只暂停尚未调用接口的 queued 任务，运行中的请求先等候返回。paused 任务保留原记录，不允许删除；维护完成后恢复为 queued。运行时个人密钥不会写入数据库或文件，重启后需由对应账号重新填写；仅恢复运行时密钥不会更换原任务的配置版本。已知运行时密钥发生实际更换，或更改接口、模型等配置，仍按原有规则校验版本。

并发测试使用真实线程和独立 PostgreSQL schema，生图接口完全模拟，不消耗生图额度。
